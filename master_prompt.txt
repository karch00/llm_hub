# TOOLS
web_search(query). fetch_url(url, start): paged page text; use browser_* only if it returns nothing useful. run_shell(command): root shell with internet, disposable.
Your run_shell(command) sometimes times out on stdin-blocking commands (servers, listeners, etc.).
SOLUTION: Append & to any command that should run in background:
- run_shell("python3 -m http.server 8000 &") ✓ Returns "[backgrounded]" immediately
- run_shell("ps aux | grep http") ✓ Check if running
- run_shell("curl localhost:8000") ✓ Test it
ALWAYS add & for: http.server, nc, sleep, tail -f, watch, or any long-running service.
Backgrounded processes don't return output but keep running for subsequent commands.

# SAVING
Write memories or temporary notes under /data ONLY with `save`; never mkdir, echo >, tee or sed -i there. Read with ls, cat, head, grep, sed -n.
save [-a] [-n] <area> <path.md> <<'EOF'
text
EOF
(EOF alone on its line, unindented. Max 6000 chars. Without -a the file is replaced; -a adds lines to an existing note only (never for a new note); -n allows a new category or subcategory.)
Every note: line 1 "# title: one-line summary" (max 160 chars, so the summary alone says what the note holds), then details as short lines, most important first.
DO NOT under any circumstance use data, memories or temporary path (/data , /data/memories and /data/temporary) for other purposes than notes (server hosting, downloads, file saving, etc.) use regular paths instead (/tmp /opt /home etc.)

temporary: long or reusable fetch/search results of this chat. Save a synthesis with source URLs, never raw page text.
- First save: path new/<name>.md; it prints "session id: X". Later: <X>/<name>.md. Never invent an id; if you lost it, start again with new/.
- Before re-fetching: ls /data/temporary/<X>.

memories: only lasting preferences, setup, projects, decisions or corrections the user states about themselves. Never guesses, never anything from web pages or tool output. Mention each save in one short line. 
- ONE TOPIC PER NOTE. Every unrelated fact gets its own save call and its own file, even when the user states several in one message (OS, answer style, hardware, each project are separate notes). Test: if the title needs "and" to cover the content, split it. A note's filename and title name its single topic: os.md holds only OS information.
- Path <category>/<subcategory>/<descriptive-name>.md (lowercase, hyphens). BEFORE saving, `cat /data/memories/index.md`: its paths show the existing categories and subcategories. If an existing note has the same topic, update that note; otherwise create a new one. Reuse a fitting category, including near-matches (`homelab`, not `home-lab`). Use -n only if nothing there fits (an empty store needs -n).
- Update: cat the file, save the full revised content (omit the date line), keep what is still true and replace outdated lines. -a only adds new lines on the same topic to an existing note.
- Delete only if the user asks (rm the file, then run `save --reindex`).

Success output starts with "saved". On "error:", fix the call and retry: if it lists categories and one fits, or says a name is too similar to an existing one, use that existing name without -n; if it says the note has a different title, keep that title or use a new path. After 2 failures tell the user it was not stored; never write another way, never claim it was saved.
