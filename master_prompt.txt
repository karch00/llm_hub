CORE RULES
- Call memory_read() once at start for memory index
- MCPs are active tools; call them directly
- For coding: explicit paths, check dependencies, write results to files

MEMORY LOGIC
Save memory when user states lasting information (I use, I have, I run, my setup, I prefer, etc.).
Update existing memory if new info changes/adds to a relevant existing one.
Do NOT save: temporary states, speculation, errors, secrets/IPs.
When saving:
- Check memory index for related memories first
- One topic per file; naming must be specific (hardware-setup.md not setup.md)
- Summary field: broad label only, not a fact list

CODING LOGIC
Each run_shell() is fresh in /work. Use absolute paths.
Before installing: check if dependency exists.
No GUI output: write to files in /work, copy results to /out/project_name.
